# Unit 4 课堂服务基础架构

首期目标是一间约 60 人的教室能开课、让学生独立完成短回合、揭晓结果，并在课末抽奖。本页是实施约定。现有本地课堂原型已有房间、单选、样课和离线入口。

## 1. 一个服务，三个入口

```text
主持台 ── 开房、发起、锁定、揭晓 ──┐
学生端 ── 入场、独立玩、提交成品 ──┼── Node.js 课堂服务 ── SQLite
投影端 ── 读取题面、进度和结果 ────┘
```

用同一个服务提供页面与接口。房间码用来找课堂。主持、学生、投影使用各自的场次凭证，投影只读，学生刷新后恢复自己的身份。教师答案和未揭晓的结果由服务端按权限发放。

SQLite 持久保存场次、参与者、每轮活动、已确认提交、锁定结果和抽奖结果。各端用 HTTP 读取当前状态和提交操作，沿用现有 SSE 通知页面更新。连接中断时可轮询，重连时读取最新授权状态。

## 2. 一份教案，几种通用模块

教案用 JSON 按顺序列出环节。每步写明模块版本、题面或素材，以及需要引用的前序结果和备用内容。开房时固定教案版本，之后可以在同一房间推进或跳过环节。

```text
Reading 2
├─ 讲解     展示一段材料
├─ 书评题   收一次个人选择
├─ 揭晓     展示本轮结果，跳过书评题时用预设对照
└─ 个人短关 保存一份取景、排版或短答成品
```

模块声明所需配置、接受的结果和可见时机。首期做展示、单选和个人提交。取景、印刷和 3D 等效果由浏览器负责，服务只接收成品编号或简短结果。学生各自完成，主持到时即可推进。投影可以对照本班的匿名成品。迟到者直接进入当前环节。

## 3. 一次回合怎样收场

1. 主持发起环节。每次发起都分配新运行编号，重复发起同一道题也各有记录。
2. 学生提交。服务校验身份、运行编号、开放状态及提交内容，保存后才返回确认。已确认的请求即使在锁定后重试，也返回原回执。
3. 主持锁定。锁定和提交由同一个数据库决定先后，锁定时保存结果和实际作答人数。揭晓时投影读取这份结果。
4. 下一环节可引用指定轮次的已揭晓结果。跳过或结果暂不可用时用备用内容，零人作答显示零份。

## 4. 参与与抽奖

**完成任意一次有效个人回合，获得一张等概率票。** 依据是服务已确认的答案或成品。纸面产出可以由主持按同一参与编号补记。每人每场最多一票，所有合格者等权。

课末由主持确认并冻结票池。服务随机抽取不同的参与者并保存结果，投影随后展示匿名中奖编号。刷新、重试和双击沿用同一次开奖。分组或匿名接力可作为独立玩法按需接入。

## 5. 开发、验收与开课

- **改教案**时校对题面、顺序和备用内容。**加模块**时先独立预览，再放进一份教案。**改公共服务**时检查旧教案、权限、并发收答和恢复。
- 本地 `unit4-classroom` 参考分支用 `npm run unit4` 开预览，用 `npm run check` 和 `npm run test:unit4` 跑已有检查。首期用同一份样例教案验收换题、跳过、锁定揭晓、重试、刷新和开奖。
- 正式上课前用真实手机和投影走一遍。发布时记录程序、教案和素材版本，课间更新并保留数据备份。若课堂网络断开，由主持明确切换到纸面并记录人工结果。恢复后从下一环节继续。
- 先在单机或教室局域网验证。集中托管时使用独立的 Unit 4 入口和数据目录。出现实测的多班写入瓶颈或跨主机容灾需求时，再评估 PostgreSQL 和多实例。

首期完成的标志是一堂课能走完 **开房 → 各自玩 → 锁定揭晓 → 抽奖**，主持能跳过环节，学生刷新能回来，断网能继续讲。
