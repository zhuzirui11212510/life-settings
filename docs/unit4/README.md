# Unit 4 课堂服务基础架构

教师可从互动作品中任选一件发到课堂。学生各自操作、即时看到个人结果，再提交本次成果。主持锁定和揭晓，大屏读取同一轮的实收统计。课末可以启用个人抽奖。

## 一个服务，三个入口

```text
主持台 ── 开房、发起、锁定、揭晓 ──┐
学生端 ── 入场、独立玩、提交结果 ──┼── Node.js 课堂服务 ── SQLite
投影端 ── 读取题面、进度和结果 ────┘
```

房间码用来找课堂。三个入口按角色读取数据，投影端只读，学生用原浏览器凭证恢复自己的身份和答卷。教师答案和未揭晓结果由服务按权限发放。页面通过 HTTP 提交和读取当前状态，SSE 提醒页面刷新，断流时轮询或重连后重新读取。

SQLite 保存场次、个人参与身份、每轮活动、已确认答卷及回执、锁定结果和开奖记录。持久数据目录固定在程序发布目录之外。开房时固定教案、模块和素材版本，发布期间保留在用版本。

## 从原作品发起一轮

默认课堂包含《沿着纸带》《改写现场》《可操作的课》的 21 件作品。主持可按现场进度选择顺序。学生完成实验或任务后，作品产生一个本轮可提交的结果，例如剪开后得到的纸带形态。**揭晓是当前作品里的主持动作**。收到零份时，投影明确显示实收为零。

作品清单声明公开入口、操作提示和结果范围。开房固定清单和作品资源版本。同一房间至多一轮开放收答。主持发起请求重试沿用原轮，主动重开分配新编号。手机上的作品与课堂控件分开更新，其他学生提交时可继续当前操作。主持可锁定并揭晓、中止、重开或发起另一件作品。

## 回执、揭晓和抽奖

- **确认提交**。服务在一次数据库事务里写好答卷和回执后再显示「已收到」。同一请求丢回执后重试，可以取回原确认。首个短关只提交一份最终成品。允许改答的活动保留每轮每人的当前答案，旧回执用于确认原请求。锁定与提交按数据库决定的先后生效，锁定固定统计和分母，揭晓开放结果。
- **个人资格**。如启用一人一票，主持给每人一个本场参与编号。换设备时由主持核对本人，将新凭证关联到原编号，并撤销旧凭证。完成任一有效回合可得一票，主持可按同一编号补记纸面产出。纸面汇总用于讲评。
- **开奖**。收答和纸面补记截止后，主持核对并冻结票池。每名合格参与者一张等权票，服务随机抽取且每人最多中一次。服务保存结果后才在投影展示匿名编号，刷新和重复开奖读取原记录。资格或结果有疑问时延后，已经公布的结果保留并核对。

## 课堂中断与发布恢复

课堂接管、程序回退和数据恢复各有自己的判据。断网时主持决定转纸面或跳过，保留线上已经确认的事实。恢复联网后先关闭中断的旧轮，再接下一环节。技术负责人判断旧程序是否兼容当前数据，只有数据确实需要恢复时才评估备份时点及其后的缺失记录。[恢复决策与反例](recovery.md)

先在单机或教室局域网验证。托管使用 Unit 4 独立入口和数据目录。后续实测出现多班写入瓶颈或明确需要跨主机接管时，再评估 PostgreSQL 与多实例。

## 首期验收

先用真实手机试玩一件作品，观察学生能否听一句指令各自开始、主持能否按时结束、投影能否带着结果继续讲解。再验证半班已提交时中断、丢回执重试、身份核对，以及换版本后仍能读出原房间。检查学生和投影在锁定前只看到允许公开的数据。约 60 人和校园网条件需在现场或相符环境验证。

可用实现及入口见[开课、联调和扩展说明](run.md)。改教案时预览受影响环节，加模块时先独立试玩再入课，改服务时检查答卷、权限和已有房间的恢复。
