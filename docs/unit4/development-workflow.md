# Unit 4 课堂服务开发流程 v1

适用于新增或改编教案、开发课堂模块，以及修改权限、同步和数据等平台能力。每次改动用一张任务卡跟进，按影响范围选择验证场景。内容负责人、开发者和试讲主持可以由同一人兼任。

[后端架构](backend-architecture.md) · [模块与教案接口](module-contract.md)

## 从教学任务到复盘

| 阶段 | 产出 | 完成条件 |
| --- | --- | --- |
| 教学设计 | 任务卡、题面或素材、主持动作 | 写清教材位置、预计用时、学生动作和可观察产出，以及跳过或断网后如何继续。 |
| 教案编排或模块设计 | 教案配置，或模块清单加最小示例 | 明确使用的版本、输入输出、可见阶段及缺省行为。平台变更补充受影响的旧版本与迁移办法。 |
| 开发与独立预览 | 可预览的教案或独立运行的模块 | 用样例数据跑通主流程。改动提交时附预览入口或复现步骤、预期结果和实际结果。 |
| 自动检查与整课联调 | 自动检查结果、三端联调记录 | 用独立的主持、学生、投影会话跑受影响流程。检查切换、刷新、跳过、权限和数据绑定。 |
| 试讲与发布 | 固定版本的试讲包和现场记录 | 技术检查通过后发试讲版。正式课就绪依据真机扫码、后排投影、主持接续和离线备用演练记录。 |
| 课后复盘 | 实际用时、学生产出、具体问题和下一项改动 | 记录在哪个环节、什么条件下出现问题。优先处理阻断课堂或影响学生判断的问题。 |

## 按改动选择验收深度

| 改动 | 开发范围 | 重点验证 |
| --- | --- | --- |
| 换题、换素材、增删或调整环节 | 教案配置和素材 | 题面、教学用时、模块引用、绑定顺序和备用流程。 |
| 增加交互、作答或结果规则 | 模块清单、界面与规则 | 独立预览、输入输出、各角色看到的状态、锁定、重连。用一个包含上下游环节的教案验收。 |
| 改房间权限、通用接口、数据库或部署 | 平台服务 | 旧教案和模块兼容性、场次隔离、提交一致性。按影响范围做并发、迁移和恢复演练。 |

本地课堂参考分支用 `npm run unit4` 启动，`npm run check` 和 `npm run test:unit4` 是已有的检查入口。首期实施时加入清单与教案验证，以及受影响模块的自动检查。联调用测试房间和独立数据目录。记录分别标明自动化、本机三端、真实教室三类验证，以及待验证项。

## 首期实施与可复现验收

1. 用 **投影讲解 → 书评投票 → 按班级结果讨论 → 英文退场条** 固定第一份样例教案和模块接口。适配已有的单选逻辑与工作室挂载。
2. 实现教案校验、按配置启动、投票分布绑定和缺省讨论题。用同一套代码验证插入讲解、换一道同类型题、跳过投票。
3. 补提交回执、原子锁定、角色快照和重连。先在独立数据目录试讲，验证新房和旧入口的行为，再把新开房间逐步切到 v1。
4. 接入《第二版》验证复杂前端交互的复用。分组活动用来验证按组收答和私有线索权限。

每次验收记录应用版本、教案版本、运行环境、命令或操作、预期与实际结果。首期最低用例包括：

| 操作 | 预期结果 |
| --- | --- |
| 建测试房，主持发起书评题，两个学生分别提交 A 和 B。揭晓前从投影读状态，随后锁定并揭晓。 | 揭晓前只能看到授权人数，直接揭晓被拒绝。揭晓后 A 和 B 各一份，分母为 2。 |
| 模拟一份已写入答卷丢回执，锁定后用原请求编号重试。再用新请求编号提交同一轮。 | 原请求得到原回执，新请求报告已锁定。结果仍是两份。 |
| 进入讨论，刷新投影与手机。另开一个房间，再发起一轮同题。 | 当前环节、已授权结果和身份恢复。两房结果独立。新轮次有独立编号。 |
| 只改教案配置，插入讲解、换题或跳过投票。 | 同类型结果可继续传给讨论。跳过时使用预设问题。原有退场条可继续提交。 |
| 用学生身份检查接口和资源，再进入真实教室测试。 | 教师答案和未揭晓结果按权限发放。真实扫码、投影可读性、断网和现场接续单独记录。 |

## 发布与回退

发布记录固定应用、教案、模块和素材版本，附试讲状态。有数据变化时记录迁移和恢复办法。开课绑定已发布版本，正式上课使用新房间，升级放在场次之间。回退优先切回兼容的程序或教案版本并保留已确认答卷。备份恢复单独记录实际可恢复时点。

首期完成的标志是样例课能完整运行，三种编排变化能通过教案配置完成，主持、学生和投影刷新后能回到正确环节，并有可重跑的验收记录。
