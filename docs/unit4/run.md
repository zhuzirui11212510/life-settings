# Unit 4 开课、联调和扩展

## 按教案试讲

主持台可选择「今晚谁来接灯？」开课。学生在手机上为夜读会节目单选原稿细节，主持揭晓本轮实收，再带同学回 Reading 2 pp.103–104。试讲台词、课本定位和试玩入口见[《今晚谁来接灯？》](lantern-lesson.md)。

## 把作品发给全班

使用 Node.js 24 或更新版本。在仓库根目录运行 `npm run unit4`，打开 `http://127.0.0.1:8794/?mode=host`。用 `npm run unit4:lan` 可让同一网络内的手机访问。选一个手机能打开的局域网地址，再扫投影上的二维码。试讲前先用一台真实手机确认网络互通。

1. 在主持台选择「课堂互动作品」开房，可以从三套作品任意选。也可以只为某一套作品开房。
2. 把投影链接打开到大屏，学生扫码入场。用主持台的作品下拉框发起一轮。
3. 学生在原作品里操作。完成关键动作后，手机显示该次结果并开放提交。比如《沿着纸带》实际剪开后，会提交一条长环、两环相套或两个独立环中的一种。
4. 主持确认实收份数，锁定后揭晓。可以重开当前作品、发起另一件，或结束课堂。学生可在独立试玩入口练习所有作品。

主持台保存本场凭证，也可下载一份私下保管，换浏览器时输入房间码和主持凭证接管。学生刷新后凭原浏览器身份找回已提交或待确认的结果。未提交的操作进度留在当前作品页面，继续操作时请保持该页面打开。转纸面后关闭被中断的线上轮次，分别记录两个来源。中断处理见[恢复决策](recovery.md)。

可选的个人抽奖使用主持分发的一次性参与链接。换设备时先核对参与编号，再签发新链接。经核对的纸面个人产出可给原编号补记资格，纸面总数单独用于讲评。课程结束后核对并冻结票池，再公布中奖编号。

## 本机或托管设置

| 参数 | 默认行为 |
| --- | --- |
| `UNIT4_HOST` | `127.0.0.1`。局域网启动时为 `0.0.0.0` |
| `UNIT4_PORT` | `8794` |
| `UNIT4_DATA_DIR` | 用户目录下的 `.life-settings/unit4`。托管可配置独立的绝对路径 |
| `UNIT4_ADVERTISE_LAN` | 局域网启动时提供当前可选 IPv4 地址，托管默认为关闭 |
| `UNIT4_READ_ONLY=1` | 打开已有数据库作恢复核对，阻止修改和补交 |

托管时给 Unit 4 单独的站点入口，把静态文件、`/api` 和 SSE 都转发给同一进程。使用 HTTPS，关闭事件流缓冲与缓存，代理读取超时应大于 15 秒的心跳间隔。每个数据库由一个 Unit 4 服务进程对外提供服务。主持和投影应使用同一实际站点地址。

发布前记录提交、教案与模块版本，以及 `/api/health` 返回的 `databaseId` 和 `schemaVersion`。数据库文件为 `classroom.sqlite`。停服备份时保留数据目录内容，运行中使用 SQLite 的在线备份功能。恢复到隔离目录后用 `UNIT4_READ_ONLY=1` 启动，核对原房间、已收答卷、揭晓记录和中奖编号。

## 发布或更新一件作品

- 各套作品位于 `unit4/public/demos/<作品集>/vN/`。该目录的 `manifest.json` 记录作品 ID、入口、操作提示与可提交结果。`unit4/demo-catalog.mjs` 读取清单，生成课堂的可选作品。发布新版时增加版本目录并保留旧目录，更新组合课堂版本。房间保留开课时的资源路径和结果范围。
- 作品从原有操作产生可提交结果时调用 `Unit4Demo.publish(id)`，结果失效时调用 `Unit4Demo.reset()`。客户端核对当前作品和消息来源，服务端核对轮次和清单里的结果范围。作品的本地计算和视觉反馈由作品自身负责。
- `unit4/store.mjs` 管理角色、轮次、回执和抽奖事务。`unit4/server.mjs` 提供 HTTP 入口和作品资源。SSE 发送房间修订号，客户端随后读取自己的角色状态。重连时重新读状态，无法建立流时使用轮询。

## 联调

```bash
npm ci
npm run check
npm test
npm run test:unit4
```

验证范围包括 21 件作品入口、结果校验、跨作品切换、角色隔离、60 个实时连接、集中提交与锁定、丢回执重试、身份换绑、纸面记录、开奖后重启和旧版本资源恢复。现场试讲另记录校园网扫码、多台实体设备和 3D 实验表现。
