# Unit 4 开课、联调和扩展

## 开一场 Reading 2

使用 Node.js 24 或更新版本。在仓库根目录运行 `npm run unit4`，打开 `http://127.0.0.1:8794/?mode=host`。用 `npm run unit4:lan` 可让同一网络内的手机访问。选一个手机能打开的局域网地址，再扫投影上的二维码。试讲前先用一台真实手机确认网络互通。

| 环节 | 学生动作 | 主持和投影 |
| --- | --- | --- |
| 先看谁在说 | 打开 Reading 2，找研究材料所在段落 | 主持从等候页进入讲解 |
| 给同一幕配头版（约 40 秒） | 试排两种英文头版，选一份最终成品提交 | 确认实收份数，锁定再揭晓 |
| 头版如何改变读者预期 | 引用原场景里的动作，比较不同头版 | 展示已揭晓的线上结果。跳过或中止时用预设讨论题。零份答卷时标出实收为零 |
| 证据能支持哪一句 | 选出样本支持的陈述，和同桌口头说明 | 锁定后揭晓选项分布和证据边界 |

主持台保存本场凭证，也可下载一份私下保管，换浏览器时输入房间码和主持凭证接管。学生刷新后凭原浏览器身份找回答卷。手机上出现「待确认」时可以重试，服务会用原请求编号核对。转纸面后关闭被中断的线上轮次，分别记录两个来源。零结果、跳过和中断的处理见[恢复决策](recovery.md)。

可选的个人抽奖使用主持分发的一次性参与链接。换设备时先核对参与编号，再签发新链接。经核对的纸面个人产出可给原编号补记资格，纸面总数单独用于讲评。课程结束后核对并冻结票池，再公布中奖编号。

## 本机或托管设置

| 参数 | 默认行为 |
| --- | --- |
| `UNIT4_HOST` | `127.0.0.1`。局域网启动时为 `0.0.0.0` |
| `UNIT4_PORT` | `8794` |
| `UNIT4_DATA_DIR` | 用户目录下的 `.life-settings/unit4`。托管可配置独立的绝对路径 |
| `UNIT4_ADVERTISE_LAN` | 局域网启动时提供当前可选 IPv4 地址，托管默认为关闭 |
| `UNIT4_READ_ONLY=1` | 打开已有数据库作恢复核对，阻止修改和补交 |

托管时给 Unit 4 单独的站点入口，把静态文件、`/api` 和 SSE 都转发给同一进程。使用 HTTPS，关闭事件流缓冲与缓存，代理读取超时应大于 15 秒的心跳间隔。每个数据库由一个 Unit 4 服务进程对外提供服务。主持和投影应使用同一实际站点地址。

发布前记录提交、教案与模块版本，以及 `/api/health` 返回的 `databaseId` 和 `schemaVersion`。数据库文件为 `classroom.sqlite`。停服备份时保留数据目录内容，运行中使用 SQLite 的在线备份功能。恢复到隔离目录后用 `UNIT4_READ_ONLY=1` 启动，核对原房间、已收答卷、揭晓记录和中奖编号。

## 添加教案和模块

- 教案位于 `unit4/lessons/`。`reading-2.json` 演示头版和退场题，`reading-2-workshop.json` 演示插入讲解、替换题目和改变讨论来源。发布改动时使用新版本号。开房时服务保存完整教案，旧房间从已固定的版本恢复。
- `unit4/lessons.mjs` 校验环节、模块版本、选项和讨论绑定，并按角色生成题面。`unit4/public/view.js` 负责显示活动和结果。新增作答方式时补配置校验、服务端验答和对应呈现，保留旧模块版本的读取行为。
- `unit4/store.mjs` 管理角色、轮次、回执和抽奖事务。`unit4/server.mjs` 提供 HTTP 入口。SSE 仅发房间修订号，客户端随后读取自己的角色状态。重连时重新读状态，无法建立流时使用轮询。

## 联调

```bash
npm ci
npm run check
npm test
npm run test:unit4
```

验证范围包括角色隔离、60 个实时连接、集中提交与锁定、丢回执重试、身份换绑、纸面记录、开奖后重启，以及同一数据库在兼容版本下恢复。现场试讲另记录校园网扫码和多台实体设备操作。
