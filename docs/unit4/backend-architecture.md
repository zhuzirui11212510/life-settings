# Unit 4 课堂服务后端架构

本文是首期实施设计。参考基线为本地 `unit4-classroom` 的 `c7e57dd`。该基线有独立的 Unit 4 服务、购物与书评两轮课堂题，以及可发起的工作室样课。课堂按约 60 人、45＋45 分钟设计。10 间教室同时上课用于后续容量验证。

## 当前实现与首期决策

| 当前实现 | 首期设计 |
| --- | --- |
| `unit4/room.mjs` 用 Node.js 和 SQLite 运行，主课堂题固定为 `survey` 和 `reviews`。 | 保留一个 Node.js 应用。普通课堂题与样课共用活动实例、角色权限和结果规则。 |
| `unit4/activity.mjs` 已支持独立运行编号、作答、锁定、揭晓。样课通过 `mount(root, ctx)` 和 `ctx.send(choice)` 接入。 | 先适配现有挂载与提交。模块按清单声明能力，讲解和讨论也能占用教案环节。 |
| SSE 发送变更通知，每个终端随后读状态，并每 3.6 秒轮询一次。 | SSE 推送按角色生成的共享状态。个人答案由提交回执与重连快照恢复。 |
| Unit 4 默认入口为 8794，数据在 `data/unit4-preview`。原版《人生设置》使用另一入口和部署脚本。 | 本地课堂和集中托管共用 Unit 4 程序，各自配置服务、数据目录和可访问地址。 |

## 模块边界与数据

| 模块 | 持有的数据与职责 |
| --- | --- |
| 教案发布 | `lesson_release` 固定步骤顺序、模块版本、素材和数据绑定。发布时校验引用和输入输出。 |
| 房间与入场 | `class_session` 记录教案版本、教案位置、当前运行和房间版本。入场码有有效期。学生用场次内的匿名身份参与，可按需分组。 |
| 课堂运行 | `activity_run` 每次发起都分配新编号，保存生命周期、作答阶段、上游结果引用。首期每房间最多一项活动运行。 |
| 提交与统计 | `submission` 按运行、作答主体和作答项唯一。锁定事务生成不可变的 `result_snapshot`，含作答数、统计口径、结果和来源。揭晓决定结果对哪些角色可见。 |
| 操作与分发 | `command_receipt` 保存重试回执。主持操作记录状态迁移。状态读取与 SSE 从数据库生成角色视图。 |

学生、主持和投影使用同一个应用。教案位置、运行状态和答卷是数据库中的权威数据。活动规则在服务端注册，接收限定的配置和数据并返回校验、统计与角色视图。浏览器负责表现，例如《第二版》的编辑和模拟、《重影舞台》的 3D 渲染。媒体由静态资源路径分发，使用固定版本便于两节课接续。

## 写入与同步

1. **入场。** 房间码用于查找可加入场次。入场后使用场次内凭证。已入场身份通过同一恢复凭证找回。首发入场请求应与稳定的客户端入场凭证绑定，以便丢失响应后重试。
2. **提交。** 识别身份并核对场次后，在事务内先查同一主体的请求回执。同一请求重试返回原回执，同一请求编号换了载荷则拒绝。首次执行再校验运行、阶段和提交修订号。答卷、回执与状态版本一起落库。
3. **锁定。** 与提交使用同一活动写入边界。先提交成功的答卷纳入统计，锁定后的新提交返回明确错误。锁定生成快照，揭晓在同一结果上更新可见状态。重跑分配新的运行编号。
4. **分发。** 提交成功后返回回执与版本。换题、锁定、揭晓立即向授权角色推送。人数可先按 250–500 毫秒合并，只发给需要的视图。启动和重连发送授权快照，断流时用带随机间隔的轮询。丢失通知由快照补齐。

主持操作用 `controlVersion` 做并发校验，普通提交不会改变它。每份答卷用 `submissionRevision` 防止旧的改选覆盖新答案。整个房间用 `roomRevision` 给状态排序。允许跳过中间版本。重连快照的版本、阶段和内容来自同一个一致读取。

按 10 间教室、每间 62 个终端计算，现有固定轮询约产生 172 次状态请求每秒。先合并通知并共享角色快照，再根据写入延迟和长连接成本决定下一步扩容。

## 权限与发布环境

- 学生只读自己的作答和班级公开状态。小组材料只发给本组成员。投影使用只读授权。主持凭证留在管理入口，入场二维码使用普通房间入口。
- 托管版建议让页面、HTTP 和 SSE 同源，服务端用带有效期的角色凭证授权。若采用 Cookie，在写操作中校验请求来源。原生 `EventSource` 可使用同源 Cookie。课堂令牌与个人答案不进入 URL 或普通访问日志。
- 教师答案与尚未揭晓的材料通过角色接口或教师包发放。验收检查实际响应和学生资源包。当前参考实现的 `unit4/lesson-data.js` 与 `unit4/handout.html` 含教师答案，托管前应明确可公开文件清单。
- 局域网与托管房间各有唯一收答服务。网络中断后，主持可以把未完成的线上轮次标记为中止，另开举牌轮次。人工统计记录参与范围和来源，恢复联机后从下一环节继续。

## 容量与迁移

| 场景 | 实施策略 | 升级依据 |
| --- | --- | --- |
| 单机试讲与局域网 | Node.js、SQLite WAL、本机持久盘。独立数据目录，做一致备份和恢复演练。 | 需要集中访问或维护。 |
| 集中托管 | 同源 HTTPS，Unit 4 独立服务。静态媒体按版本缓存。反代对 SSE 关闭缓冲，心跳间隔短于空闲超时。 | 多房写等待持续影响提交指标，或出现跨主机容灾需求。 |
| 多实例 | PostgreSQL 共享课堂状态。初期用 `LISTEN/NOTIFY` 广播房间及版本变化，各实例仍从数据库恢复快照。 | 长连接或广播负载达到实测瓶颈时评估拆分。导出需要可靠重试时引入持久任务。 |

迁移先做新房间。把现有两轮单选和工作室接入适配层，在独立数据目录用 v1 试讲。对照旧入口验证入场、锁定、结果与导出后，在课间把**新建房间**切到 v1，已开房间沿用原入口至结束。保留旧库及导出。旧活动的 `closed` 可能来自开放、锁定或揭晓，历史状态缺失时标为未知。回退优先恢复兼容的程序或教案版本，数据库恢复按备份可恢复时点单独处理。

## 验证边界

参考实现已有本机 60 路集中入场、作答与重试测试，以及单条 SSE 和进程重启的覆盖。v1 目标是在约定网络条件下，60 人满班集中作答时提交 p95 ≤ 500 ms，阶段同步 p95 ≤ 1 秒，网络恢复后 5 秒内回到正确阶段。锁定、请求重试和进程重启的测试应验证已确认答卷零重复、零丢失。真机网络、反代链路和多房长连接单独记录。
