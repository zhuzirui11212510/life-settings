# Unit 4 课堂中断与恢复决策

课堂可以改变接下来的讲法。已经收下的答卷、已经揭晓的统计、已经公布的中奖结果，要能说清来源和处理结果。遇到故障时，先确定影响的是上课进度、程序版本还是数据。

| 情况 | 谁判断 | 如何处理 | 怎样才算恢复 |
| --- | --- | --- | --- |
| 学生进不去、主持掉线或投影卡在旧轮 | 主持 | 确认主持台和投影回到同一轮，抽查学生手机，再按实际能参与的人数和剩余时间决定继续、转纸面或跳过。 | 课堂有清楚的下一步，学生知道当前用哪种方式参与。 |
| 更新后程序出错，当前课堂数据库仍可用 | 技术负责人 | 保留当前数据库。旧程序与当前数据库、教案、模块和素材的兼容性有证据时，才切回旧程序。 | 能打开同一原房间，核对原轮次、已确认答卷、已揭晓结果和已公布中奖编号。另用测试房验证写入。 |
| 数据库损坏或丢失 | 技术负责人核对数据，主持核对现场结果 | 保留现有残存数据和现场记录，确认备份时点与可能缺失的内容。在隔离位置验证备份，再判断能否恢复服务。 | 已找回的房间与结果可以核验。备份之后的缺口已列明，公开过的结果有对应的核对记录。 |

发布记录包含程序版本、数据结构版本、实际数据目录、教案和素材版本。更新和切换安排在课间。兼容性在当前库的隔离副本上验证。切换期间暂停线上收答，保留较新的数据库与原版本。旧程序无法读取当前库时，课堂沿用替代方式，技术负责人修复可用版本。选择备份时由技术负责人说明恢复时点，主持确认缺失记录对本场和公布结果的影响。备份恢复后的旧轮先留作只读核对，即使备份中仍为开放状态。续课沿用纸面或另开新场次。

## 半班已提交后断网

1. **主持先给课堂一个明确指令。** 能联系服务时，先确认线上锁定，再转纸面或跳过。主持端连不上服务时，可以宣布转纸面。服务器此刻可能仍在接收部分学生的请求。
2. **纸面另记一轮。** 记录来源和实际参与范围。例如线上实际收到 41 份、纸面收到 15 份，两笔分别列。两边可能有人重叠。没有个人编号的举牌总数只用于讲评。
3. **恢复后先处理旧轮。** 服务恢复可达后关闭中断的线上轮，保留它已收到的答卷并标明中断。正式课堂从下一环节接续。若旧轮已经揭晓，保留已揭晓记录。后续发现错误时另记更正及原因。
4. **已确认事实依然有效。** 线上已确认的有效产出按开课时的规则核对资格，主持核验的纸面个人记录用同一编号去重。线上答卷是否进入当堂讲评，与个人是否完成过有效产出分别判断。票池无法核实时延后开奖。

## 恢复后投影能亮，还要核对什么

- **回执。** 同一参与者、同一轮、同一请求编号、同一内容，已经存下的提交应能找回原确认。同一编号换内容时返回冲突。新编号按该轮当前状态判断。页面可显示「待确认」并读回本人记录。
- **场次。** 健康接口返回正常时，还要确认服务打开的是原数据库。切换版本应能读出原场次、轮次和对应发布版本。当前 Unit 4 默认数据路径随代码目录变化，健康接口只回复服务可达，这是方案需要补齐的边界。
- **统计。** 核对实际分母、结果来源与揭晓记录。已揭晓的版本保留。纸面轮与线上轮分别展示。
- **抽奖。** 有冻结票池和中奖记录时沿用同一次开奖。若从早期备份恢复后找不到中奖记录，先核对现场保存的公示或主持记录。已公布的编号保留，证据不足时延期核对。

仓库里的原版《人生设置》服务配置使用 8787 端口。根目录的更新与回滚入口针对该服务的程序及备份时的数据。Unit 4 原型由 `unit4/room.mjs` 单独运行，默认端口 8794。它已有纸面总数入口和同版本重启用例，逐人纸面核对、跨版本兼容和备份恢复都需要各自的证据。

## 用反例检查蓝图

| 现场例子 | 预期判断 |
| --- | --- |
| 第 41 份答卷已入库，手机没收到确认，主持随后锁定。 | 同一请求能找回原确认。新提交报告该轮已锁定。线上实际分母是 41。 |
| 主持断网转纸面，少数手机仍连着服务器。 | 纸面另记来源。恢复后终止旧线上轮并保留已收记录。最终展示的统计注明范围。 |
| 学生换了手机，又凭纸面产出补记。 | 主持核对本场参与编号，合并到原来的资格。没有个人记录的纸面汇总无法发票。 |
| 旧程序能启动，健康检查正常，原房间打不开。 | 恢复尚未成立，核查数据目录和版本。课堂继续使用已经选定的替代方式。 |
| 恢复的旧备份里上一轮还开着，手机自动补交。 | 该轮只读，保留已恢复记录。续课使用纸面或新场次。 |
| 现场已经公布 #018，恢复后的备份没有这次开奖。 | 保留现场公示事实并核对来源。资格或结果无法核实时延期处理。 |

这些反例用于检查决策是否自洽。真实课堂试讲、服务在校网的表现、跨版本读取和实际备份恢复须分别留证。
